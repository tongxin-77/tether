# Tether 前端（GUI）需求文档

> 组件：`tether.exe`，Tauri 2 + TypeScript + xterm.js（`src/` + `src-tauri/`）
> 相关文档：[后台服务 daemon](daemon-requirements.md) · [管理服务器 hub](https://github.com/tongxin-77/tether-hub/blob/main/docs/requirements.md) · [索引](README.md)

## 1. 背景与目标

Tether 是面向个人的轻量 Windows 多会话终端，最初为运行 Claude Code 而做，现可运行任意 shell。会话由常驻后台进程 `tetherd` 持有，GUI 只是**查看器**：关闭窗口不结束会话，需要时（如点击系统通知）再被唤起。

目标：

- 在一个窗口内管理多个本地 / SSH 远程会话，切换、重命名、关闭直观。
- 终端体验接近 Windows Terminal（颜色、复制粘贴），并对 Claude Code 有一等支持（状态、通知、命令补全、图片粘贴）。
- 资源占用可控：GUI 不常驻也不影响会话；外观效果不以大量内存为代价。
- 尽量少让用户维护配置：连接、新建会话时除必要输入外不额外询问。

## 2. 范围 / 非目标

**范围**：会话侧栏与终端视图、新建会话入口、文件树（本地 + SFTP）、Markdown / HTML 预览、设置面板（shell、主机、外观、通知提示音、Claude Code 集成）、交互提示弹窗（密码 / 口令 / 指纹）、单实例与通知唤起。

**非目标**：

- 不持有任何会话状态或 PTY（全部在 daemon）；不直接读写 `config.json`、`~/.ssh/*`、凭据管理器、`~/.claude/settings.json`（均经 daemon）。
- 不做分屏 / 标签页内多窗格；不做多窗口。
- 不做远程文件在线编辑回传；不做传输取消（见待定项）。
- 不引入 React 等 UI 框架（Lobe UI 风格仅以 CSS token 移植）。
- 非 Windows 平台。

## 3. 功能需求

### 3.1 进程与连接

| 编号 | 需求 | 验收标准 | 状态 |
|------|------|----------|------|
| F-1.1 | GUI 通过命名管道接入 daemon；连不上时自动拉起同目录 `tetherd.exe` 并重试 | daemon 未运行时启动 GUI，数秒内连上并显示会话列表；失败时提示“无法连接后台进程” | 已实现 |
| F-1.2 | 单实例：再次启动 `tether.exe` 立即退出，已有窗口还原并前置；携带 `--session <id>` 时切到该会话 | 连续双击两次快捷方式只有一个窗口；点击通知拉起时定位到对应会话 | 已实现 |
| F-1.3 | 关闭窗口不影响会话；重新打开后由 daemon 快照恢复各会话画面 | 关窗后再开，会话仍在、画面与关窗前一致（仅当前屏，不含回滚历史，见待定项） | 已实现 |
| F-1.4 | 向 daemon 上报当前激活会话与窗口焦点，用于决定是否弹系统通知 | 窗口在前台且会话激活时不弹通知；失焦 / 切到其它会话时弹出 | 已实现 |
| F-1.5 | dev 与安装版隔离：debug 构建 identifier 为 `com.tether.app.dev`、标题 “Tether (dev)”，应用数据、WebView2 数据、单实例键独立 | dev 与安装版可同时运行、互不影响 | 已实现 |

## 4. 非功能需求

### 4.1 性能与资源预算（release 实测）

| 指标 | 预算 / 实测 |
|------|-------------|
| GUI 私有内存 | 基线约 160–175 MB（WebView2 主导），3 个会话约 194 MB |
| 空闲 CPU | < 0.5% |
| 窗口透明开销 | 半透明与不透明内存基本持平；不得采用 `backdrop-filter`（约 +95 MB） |
| 安装包 | 单个 NSIS 约 3 MB（含 daemon） |

### 4.2 安全

- Markdown 输出必须经 DOMPurify 净化，且不加载任何图片（防跟踪 / 外联）。
- 外链仅允许 http(s)，由 daemon 校验后用默认浏览器打开。
- 不启用 Tauri asset 协议。
- 密码只在提示弹窗中经管道一次性传给 daemon，GUI 不持久化。

### 4.3 兼容性

- Windows 10/11 x64，依赖 WebView2。
- 字体 Cascadia Mono → Consolas 回退。
- 管道协议与 daemon 同版本打包，不要求跨版本兼容（安装 / 升级会同时替换两者）。

## 5. 接口

- **GUI ↔ daemon**：命名管道 `\\.\pipe\tetherd-<用户名>`（dev：`tetherd-dev-<用户名>`），换行分隔 JSON，终端数据 base64。消息定义见 [daemon §4](daemon-requirements.md#4-接口gui--daemon-管道协议)。
- **daemon 同时只服务一个 GUI 连接**：新 GUI 连接顶替旧连接（单实例保证正常情况下只有一个）。
- **hub 连接**：设置中的「管理服务器」分组只编辑设置与显示状态，连接由 daemon 发起，见 [daemon §3.7](daemon-requirements.md#37-hub-客户端第二阶段)。
- **hub 接管提示**（计划中）：会话被 hub 接管时 GUI 需显示“被接管中”标识并提供“收回控制”，见 [hub §3.3](https://github.com/tongxin-77/tether-hub/blob/main/docs/requirements.md#33-远程接管)。

## 6. 待定项

1. 重连后只恢复当前屏（daemon vt100 无回滚缓冲），是否需要保留滚动历史？代价是 daemon 内存。
2. 传输不支持取消，大文件传输期间无法中止。
3. 远程打开的文件编辑后不回传，是否需要“监视并上传”。
4. `claude` 补全为静态列表（对应 Claude Code 2.1.322），版本升级需手动同步。
5. hub 接管相关 UI（被接管标识、收回控制、禁止接管开关）待 hub 设计确定。
6. 标为“已实现未实测”的条目需在真实环境补测。
